# 架构

ParanO(1)d 把每一项证明责任放到其 witness 原本所在的位置。钱包知道支出秘密，矿工持有公开状态 witness，全节点则两者都不需要：它只验证得到的证明，并物化已经证明的写入。

![证明原生区块流程](../assets/architecture/proof-native-block-flow.svg)

## 证明边界

钱包与矿工证明的是不同命题。

钱包证明自己知道每个输入所有者背后的 256 位秘密，并把授权绑定到完整逻辑交易。它不负责证明输入当前尚未花费，因为钱包无需持有当前 Merkle 路径。

矿工证明公开执行命题：输入存在、输出槽为空、数值守恒、手续费符合共识、槽位写入精确，而且得到的 UTXO 根正确。新证明内部还会验证前一个 `HistoryStep` 终端。

这种分离让私有授权始终留在本地，同时允许公开状态 witness 在交易构造与区块收录之间发生变化。

| 阶段 | 接收 | 确立 |
|---|---|---|
| 钱包 | 秘密与自有 UTXO | 一份绑定到逻辑交易的随机化授权 |
| 内存池 | `PagedSpend` 意图 | 胶囊、结构、限制、手续费与预留均可接受 |
| 矿工 | 已接受意图与活状态 | 精确状态转换与递归连续性 |
| 全节点 | 区块与终端 | `HistoryStep`、PoW 与规范父区块有效 |

## 交易与区块流程

1. 钱包选择活 UTXO，构造一个逻辑 `PagedSpend`。
2. 钱包针对 `{logical_txid, input_owner}` 构造全新的授权胶囊。
3. 内存池在保存或转发前验证完整意图。
4. 矿工选择互不冲突的意图，计算精确槽位写入。
5. 矿工证明区块关系与前一个终端，再搜索固定 Poseidon2b 区块头的 nonce。
6. 对等节点验证原子包 `{block, terminal}`，并把已证明写入应用到 MDBX。

任何对等节点都不重复钱包 proving 或矿工执行。矿工无法修复无效授权，算力也不能让无效 `HistoryStep` 获得接受。

## 递归连续性

从概念上看，终端 `T[h]` 证明三件事：

- 区块 `h` 满足公开区块关系；
- 其转换后状态根是已证明写入的精确结果；
- 终端 `T[h-1]` 对此前状态链有效。

下一个区块在自身关系中验证 `T[h]`。因此，有效性沿链递归累积，而终端形状始终固定。累计工作量仍负责在互相竞争的有效链中作出选择；递归并不替代工作量证明。

## 状态物化

验证会产生一组规范槽位写入。全节点把这些写入应用到精确的稀疏 UTXO 向量，而不是再次执行交易逻辑。

槽位位于每段 `2^16` 条记录的分段中。空段是虚拟的；清除最后一个占用槽会删除该段；分配输出时会先复用空槽，再扩展状态。新的 `creation_id` 可防止旧引用在同一索引复用后重新生效。

节点保留用于累计工作量比较的紧凑区块头，以及用于常规同步和浅层重组的最近 18 个完整区块。更早的交易体不是活跃共识所需数据。付款收据可以在区块体离开保留窗口后，继续提供可独立验证的包含证据。

## 加入网络

较小的高度差通过保留的完整区块补齐。差距较大时，新节点把区块头与活状态认证快照写入 staging；安装状态前，它会验证累计工作链、最终确定边界和匹配的 `HistoryStep` 终端，随后正常验证近期后缀。

快照不是可信状态。它只是状态的传输载体，其状态根和历史边界都由共识认证。

## 挖矿边界

矿工先证明所有与 nonce 无关的数据。之后，PoW 只搜索固定 Poseidon2b 区块头的 128 位 nonce。工作量证明因此只有一个任务：排序有效状态转换。

外部矿工接收不可变、一次性模板，只返回 nonce。交易选择、状态转换、证明构造和区块转发均留在节点内。模板一经签发，外部 worker 就不能修改收益地址、交易或状态根。

## 实现组件

| 组件 | 职责 |
|---|---|
| `noid_tx` | 逻辑 `PagedSpend`、交易标识与授权绑定 |
| `noid_mempool` | 意图准入、冲突预留与转发策略 |
| `noid_miner` | 交易选择、状态 witness、区块准备与 PoW |
| `noid_recursive` | `HistoryStep` 关系、终端验证与递归 |
| `noid_chain` | 共识规则、MDBX 状态、区块头、重组与快照 |
| `noid_p2p` | GossipSub 转发、发现与同步协议 |
| `noid_node` | 运行时编排、钱包集成与关闭流程 |
| `noid_rpc` | 本地节点、钱包与外部挖矿接口 |

部署说明见[在 Linux 上运行节点](../operate/node.md)。
