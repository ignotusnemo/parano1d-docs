# 网络

ParanO(1)d 使用 libp2p 完成对等节点身份、发现、转发与同步。公网协议标识为：

```text
/noid/mainnet/1.0.0
```

默认 P2P 监听 TCP `9400`。JSON-RPC 是单独的本地管理接口，监听 `127.0.0.1:9401`。

## 对等节点身份与共识身份

每个节点持久保存一个 libp2p Ed25519 对等身份。它用于认证网络会话，并在重启后维持稳定的 peer ID。

该身份没有共识权限：不能花费 UTXO、签署区块，也不能影响证明验证。钱包所有权、区块有效性和工作量证明使用的是二进制共识栈。

## 节点发现

节点综合三种发现来源：

- 内置 DNS seeds，用于首次找到公网对等节点；
- Kademlia，用于持续发现；
- mDNS，用于发现本地网络中的节点。

成功连接的地址会持久保存并复用。peer store 最多保存 500 个对等节点，并限制单个节点可记录的地址数量。

DNS 记录指向网络 endpoint，而不是链状态。只要公网地址不变，更新软件或重置节点都无需修改 DNS 名称。

## Gossip

GossipSub 传输交易意图和区块公告。

完整原子区块包小于 inline 限制时直接发送；更大的区块只公告区块头，再通过带类型的 request-response 拉取。Gossip 消息具有严格大小上限，因此恶意对等节点不能让普通转发触发无界内存分配。

只有本地内存池验证规范结构、授权和当前冲突后，交易才会转发。收到 gossip 永远不等于接受共识状态。

## Request-response 协议

带类型的交换负责：

- 批量区块头；
- 保留的完整区块；
- 快照清单与状态分段；
- 近期内存池 inventory 与缺失意图。

每批最多包含 512 个区块头。快照状态由清单和逐段认证的数据组成，而不是一个无界大消息。

对等节点连接后可以核对近期内存池内容。每个收到的意图仍必须经过常规本地准入。

## 资源边界

公网通信在多个层次上保持有界：

- 入站与出站服务各自具有响应字节预算；
- 区块与 gossip 消息大小受限；
- 状态按段传输；
- 对等地址与 peer-store 条目数受限；
- 重复无效行为会受到惩罚；
- 连接按网络组保持多样性。

出站选择中，同一网络组最多允许两个对等节点。入站服务中，同一 IP 地址最多允许八条连接，同一网络组最多 32 条。这降低了同一托管网段填满所有 peer slot 的收益。

这些限制不能替代多样化的公网拓扑。Seed 与挖矿设施仍应分布在相互独立的网络和运营方。

## 挖矿对等节点门槛

普通挖矿要求至少两个已认证对等节点。这可以防止无人值守的节点仅因网络链路中断，就继续扩展其隔离的私有视图。

该门槛是运维保护，不是投票。对等节点不会批准区块，也不能使无效转换变得可接受。连接建立后，矿工仍完全依据本地证明验证和累计工作量共识。

## 接口边界

P2P 端口 `9400` 可以公开暴露，RPC 端口 `9401` 不应公开。RPC 包含钱包与进程控制方法，本身没有面向公网的传输认证层；请保持 loopback 监听，或放在经过认证的私有隧道后。
