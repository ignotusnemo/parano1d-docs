# Стек доказательств

ParanO(1)d использует единый бинарный арифметический стек для владения,
переходов состояния, отношений Merkle, рекурсивной непрерывности и commitments
proof of work. Общее поле — бинарное башенное поле `GF(2^128)`.

![Стек доказательств ParanO(1)d](../assets/architecture/proof-stack.svg)

## Poseidon2b

Poseidon2b является общей перестановкой:

| Параметр | Значение |
|---|---:|
| Ширина состояния | 4 элемента поля |
| S-box | `x^7` |
| Полные раунды | 8 |
| Частичные раунды | 58 |

Типизированные доменные теги разделяют адреса, физические страницы, логические
транзакции, узлы Merkle, commitments состояния, идентификаторы блоков,
PoW-digest и proof transcript. Общая перестановка не означает общий
хеш-домен.

## FROST-GKR

FROST-GKR выражает пакетные исполнения Poseidon2b и Merkle-пути как прямые
отношения степени семь над общими булевыми гиперкубами. Это используемая
ParanO(1)d committed-column reduction, а не послойное повторение схемы.

Редукция сохраняет multilinear extension и sumcheck-механику GKR, но заменяет
рекурсивный спуск по слоям схемы глобальными отношениями над execution trace.
Общие столбцы позволяют проверять множество перестановок и путей без отдельного
constraint sumcheck для каждого экземпляра.

## Замыкание отношения

Дальнейший pipeline объединяет:

- пакетный sumcheck;
- zerocheck;
- lincheck;
- FRI-Binius/BaseFold над бинарным полем.

Полученная система доказательств прозрачна и не требует trusted setup.
Релизные бинарники содержат аутентифицированные matrix pack B64 и B255 вместе
с ожидаемыми digest. Сборка с другим pack не может незаметно представить его
как каноническое отношение.

## Авторизация кошелька

Кошелёк доказывает знание 256-битного прообраза `input_owner`, привязанного к
идентификатору логической транзакции. Доказательство каждый раз
рандомизируется заново, скрывает witness и не содержит state path.

Сериализованная авторизация остаётся ниже худшей границы в 61 000 байт. Wire
format допускает до 256 КиБ, чтобы декодирование имело явный предел и при этом
оставалось место для канонического proof object.

## HistoryStep

Block prover устанавливает полный публичный переход и проверяет предыдущий
терминал внутри нового отношения. Следующий терминал тем самым связывает:

```text
previous validity
        +
current block relation
        +
exact post-state
```

Размер доказательства и проверка терминала не растут вместе с высотой цепочки.
Постоянные заголовки остаются вне рекурсии для накопления proof of work и выбора
ветви.

## Учёт безопасности

Исполняемый
[реестр звуковости](https://github.com/ignotusnemo/parano1d/blob/main/noid_gkr/src/zk_auth_qrom.rs)
фиксирует границы уровня проекта:

| Компонент | Граница |
|---|---:|
| Базовый IOP кошелька | 95 бит |
| Авторизация кошелька в QROM | 79 бит |
| `HistoryStep`, классическая модель | 100 бит |
| `HistoryStep` в QROM | 83 бита |
| Прообраз Poseidon2b, постквантовая модель | 128 бит |
| Коллизия Poseidon2b, постквантовая модель | 85 бит |
| Полная цепочка доказательств консенсуса | **79 бит** |

Композиция использует самую слабую применимую границу. Опубликованный
результат — доказанная инженерная нижняя граница постквантовой стойкости в 79
бит для всей цепочки консенсусных доказательств, закреплённая этим реестром.

Границы утверждений и допущения вне proof-системы описаны в
[модели безопасности](../protocol/security-model.md). Crate реализации
перечислены в разделе [«Структура workspace»](../developers/workspace.md).
