# Конфигурация

Core читает конфигурацию TOML из:

```text
~/.parano1d/parano1d.toml
```

если другой файл не указан через `--config`. Отсутствующий файл создаётся
атомарно с безопасными значениями по умолчанию. Некорректный TOML останавливает
запуск и никогда не заменяется молча.

## Полный файл

```toml
[network]
listen = "0.0.0.0:9400"
seeds = []
max_peers = 50

[storage]
backend = "mdbx"
path = "~/.parano1d/data"

[rpc]
listen = "127.0.0.1:9401"

[mining]
enabled = false
miner_address = ""
```

Аргументы командной строки имеют приоритет над соответствующими параметрами
файла.

## Сеть

`network.listen` принимает `HOST:PORT` или multiaddress libp2p. Для публичных
IPv4-соединений используйте `0.0.0.0:9400`.

`network.seeds` добавляет начальные пиры. Допустимые формы:

```text
198.51.100.10:9400
seed.example.org:9400
/ip4/198.51.100.10/tcp/9400
dnsaddr:seed.example.org
```

Встроенные DNS-сиды доступны всегда; пользовательские адреса дополняют их.

По умолчанию `max_peers` равен 50. Увеличение значения требует больше
дескрипторов, памяти соединений и ресурсов публичного обслуживания, но не
увеличивает вес узла в консенсусе.

Повторяемый параметр `--seed HOST:PORT` добавляет адреса к настройкам файла.

## Хранилище

В рабочей конфигурации `storage.backend` имеет значение `mdbx`. RAM-backend
предназначен для тестов и не сохраняет состояние узла.

В `storage.path` находятся база цепи, артефакты кошелька, идентичность пира,
кеш доказательств и staging снимков. Два запущенных узла не должны использовать
один каталог.

Параметр `--data-dir` переопределяет этот путь.

## RPC

Оставляйте RPC на:

```text
127.0.0.1:9401
```

Интерфейс позволяет отправлять транзакции кошелька и управлять процессом. Это
не публичный API эксплорера с общей системой аутентификации.

При внешнем майнинге весь RPC можно защитить параметром `--mining-key`.
Bearer-токен не шифрует транспорт. Для удалённого worker используйте loopback,
приватную сеть, SSH-туннель или аутентифицированный TLS-прокси.

## Майнинг

Режим процесса задаётся явно:

```sh
parano1d --mode node
parano1d --mode miner
parano1d --mode extminer --mining-key TOKEN
```

Устаревшее поле `mining.enabled` не переопределяет `--mode`. Пустой
`miner_address` использует активный адрес кошелька. Параметр
`--miner-address` задаёт выплату для текущего процесса.

`--cpu-threads N` ограничивает общий CPU-пул встроенного майнера. На обычный
режим узла и отдельный внешний worker он не влияет.

## Логи

`--log` принимает фильтры `error`, `warn`, `info`, `debug` и подобные.
Начинайте с `info`. Уровень `debug` полезен для ограниченной диагностики, но
создаёт значительно больше записей.

Под systemd вывод попадает в journal. GUI перенаправляет собственный узел в
`parano1d-node.log` выбранного каталога данных.

## Предварительная проверка

Поддержку процессора можно проверить без создания конфигурации, кошелька и
базы:

```sh
parano1d --check-hardware
```

Успешный отчёт заканчивается строкой `NODE READY`.
