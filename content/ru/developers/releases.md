# Подготовка релизов

Одна ревизия исходного кода создаёт две продуктовые линии для пяти нативных
платформ:

- архив Core: узел, CLI и внешний майнер;
- пакет GUI: приложение кошелька и приватный узел.

Релизные артефакты собираются из существующего аннотированного тега версии и
одного аутентифицированного pack HistoryStep.

## Поддерживаемые платформы

| Система | Core | GUI |
|---|---|---|
| Linux x86-64 | `.tar.gz` | `.deb` |
| Linux ARM64 | `.tar.gz` | `.deb` |
| Windows x86-64 | `.zip` | установочный `.exe` |
| macOS Apple Silicon | `.tar.gz` | `.dmg` |
| macOS Intel | `.tar.gz` | `.dmg` |

Все пакеты используют версию workspace из `Cargo.toml`.

## Подготовка исходного кода

Перед созданием тега:

1. обновите версию workspace и примечания к релизу;
2. запустите форматирование, проверку workspace и тесты изменённых crate;
3. выполните применимые live-сценарии;
4. аутентифицируйте канонический pack матриц;
5. убедитесь, что diff чист и намерен;
6. создайте аннотированный тег `vMAJOR.MINOR.PATCH`.

Версия в теге и пакетах должна совпадать точно.

## Pack матриц

Релиз использует один архив:

```text
history-step-pack-v1.tar.gz
```

Его SHA-256 — явный вход workflow. Каждый нативный runner независимо
распаковывает и аутентифицирует pack. Runtime-метаданные и два leaf-digest
матриц должны совпадать с `pins.env`.

Релизная сборка встраивает аутентифицированные байты в `parano1d`; пользователю
не нужно загружать матрицы при первом запуске.

## Проверка платформ

Запустите ручной workflow **Platform CI** на commit с тегом. Он проверяет:

- переносимые флаги сборки;
- компиляцию полного workspace;
- нативную линковку бинарников;
- поведение проверки оборудования;
- self-check GUI;
- рабочие proof-kernel на каждой поддерживаемой архитектуре;
- корректный отказ на неподдерживаемом старом виртуальном x86 CPU.

Сохраните ID успешного запуска и точный head commit.

## Черновик релиза

Создайте draft-релиз GitHub для тега и прикрепите аутентифицированный pack
матриц. Не публикуйте до завершения нативного workflow.

Запустите **Native Release**, передав:

- существующий тег;
- SHA-256 pack матриц;
- ID успешного запуска Platform CI;
- канал релиза `stable`.

Preflight требует аннотированный совпадающий тег, draft-релиз, точную успешную
ревизию Platform CI и корректный digest pack.

## Нативная сборка

Каждый runner выполняет:

```sh
./scripts/build_release.sh \
  --pack .release-ci/pack/history-step-pack-v1 \
  --output .release-ci/build \
  --skip-tests
```

Полные тесты исходного кода уже прошли на той же ревизии с тегом. Каждое
задание всё равно аутентифицирует pack, собирает полную цель, выполняет
нативные smoke-тесты, упаковывает обе продуктовые линии и загружает их в
черновик.

## Публикация

Финальное задание скачивает из черновика каждый ожидаемый артефакт, проверяет
digest pack матриц, создаёт единый `SHA256SUMS`, загружает его и только после
этого открывает релиз.

Неполный набор платформ не публикуется.

## Состояние подписей

Конвейер поддерживает необязательную identity Apple Developer ID. Без
учётных данных проекта macOS использует ad-hoc подпись приложения, а Windows
остаётся без Authenticode. Пока полноценные подписи не включены,
пользовательская документация должна описывать предупреждения первого запуска
и требовать проверку SHA-256.

## Проверка опубликованного релиза

После публикации:

1. скачайте каждый артефакт так же, как пользователь;
2. проверьте `SHA256SUMS`;
3. установите и удалите каждый GUI-пакет на нативной платформе;
4. проверьте оборудование и справку Core;
5. запустите узел с чистым каталогом данных;
6. проверьте P2P-синхронизацию, отправку кошелька, восстановление чека и
   корректное завершение;
7. сохраните логи сборки и точный digest pack вместе с данными релиза.
