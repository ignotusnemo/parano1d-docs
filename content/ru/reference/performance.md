# Измерение производительности

Производительность относится к конкретной ревизии исходного кода, профилю
доказательства, пакету артефактов, профилю сборки и машине. Она не является
константой консенсуса и не выводится только из числа ядер.

Архивные таблицы в `research/two_class/results/` получены до перехода на
штатный профиль C1. Они остаются воспроизводимыми результатами прежней
реализации, но не являются текущими штатными измерениями. Актуальные значения
нужно получать из действующего исходного кода и аутентифицированного пакета
матриц.

В отчёте следует фиксировать как минимум:

```text
git commit
версию Rust
ОС и версию ядра
модель CPU и логическую топологию
выбранную при запуске реализацию
хэш-коды пакета матриц
число образцов и режим прогрева
p50 и p95 методом ближайшего ранга
```

## Авторизация кошелька

Стенд кошелька измеряет построение страниц, логическое хэширование, одну капсулу
авторизации, полное кодирование и декодирование логической транзакции и
локальный приём капсулы. Сетевая задержка и построение `HistoryStep` не входят
в измерение.

```sh
NOID_WALLET_BENCH_SAMPLES=20 cargo run --release --locked \
  --manifest-path research/two_class/Cargo.toml \
  --bin two-class-wallet-bench
```

Штатный кошелёк C1 использует 65 запросов Fiat–Shamir. Один `PagedSpend`
содержит одну капсулу авторизации как для одной, так и для всех 128 страниц.
Каноническая сериализованная авторизация имеет верхнюю границу 92 696 байт.

## HistoryStep

Изолированный штатный стенд требует завершённый аутентифицированный пакет
матриц. Каждый класс запускается отдельно, чтобы вывод однозначно указывал
родительский и дочерний классы.

```sh
NOID_PACK_ROOT=../parano1d-artifacts/history-step-pack-v1
source "$NOID_PACK_ROOT/pins.env"
export NOID_HISTORY_STEP_PACK_DIR="$NOID_PACK_ROOT"

NOID_HISTORY_STEP_BENCH_FILTER=B64 \
NOID_HISTORY_STEP_BENCH_SAMPLES=20 \
cargo bench --locked -p bench_prover --bench history_step_proof

NOID_HISTORY_STEP_BENCH_FILTER=B255 \
NOID_HISTORY_STEP_BENCH_SAMPLES=20 \
cargo bench --locked -p bench_prover --bench history_step_proof
```

`cargo bench` использует оптимизированный профиль bench. Каждый образец
охватывает штатное построение доказательства и создание терминального
доказательства. Проверка включает ограниченное декодирование формата передачи и
полную проверку терминального доказательства. Стенд также выводит размеры
основного доказательства, C1 sidecar и число утверждений об открытии.

## Сквозное построение блока

Изолированное время доказательства не равно полной задержке майнинга. При
определении доступного класса измеряется весь путь:

```text
выбор транзакций
  + сборка трассы текущего блока
  + воспроизведение и связывание родительского терминального доказательства
  + построение HistoryStep
  + поиск nonce
  + отправка и принятие блока
```

Поиск nonce и распространение по сети изменяются независимо от построения
доказательства. Классы B64 и B255 следует проверять на полном штатном пути и на
конечной машине. Официальные бинарные файлы сохраняют переносимую базовую
реализацию и при запуске выбирают `pclmul`, `avx2+vpclmul`,
`avx512bw+vpclmul` или `neon+pmull`.
