# Интерфейсы командной строки

Архив Core содержит три исполняемых файла:

| Файл | Роль |
|---|---|
| `parano1d` | Полный узел, backend кошелька и необязательный внутренний конвейер доказательства/майнинга |
| `parano1d-cli` | Тонкий JSON-RPC-клиент работающего узла |
| `parano1d-miner` | Отдельный worker поиска nonce Poseidon2b |

## Демон Core

Обычный узел запускается без режима:

```sh
parano1d
```

Публичные параметры демона:

| Параметр | Значение |
|---|---|
| `-c, --config FILE` | Путь к конфигурации TOML |
| `--mode node` | Обычный узел без майнинга |
| `--mode miner` | Узел со встроенным конвейером доказательства и PoW |
| `--mode extminer` | Узел строит доказательство, внешний worker ищет nonce |
| `--miner` | Краткая форма `--mode miner` |
| `--extminer` | Краткая форма `--mode extminer` |
| `--miner-address ADDRESS` | Адрес выплаты; по умолчанию активный владелец кошелька |
| `--cpu-threads N` | Общий бюджет потоков встроенного майнера |
| `--data-dir PATH` | Каталог цепи, кошелька и runtime-данных |
| `--p2p-listen HOST:PORT` | P2P-listener; по умолчанию `0.0.0.0:9400` |
| `--rpc-listen HOST:PORT` | JSON-RPC-listener; по умолчанию `127.0.0.1:9401` |
| `--seed ENDPOINT` | Добавить bootstrap endpoint; можно повторять |
| `--log LEVEL` | Фильтр tracing: `error`, `warn`, `info`, `debug` и другие |
| `--mining-key TOKEN` | Требовать bearer-токен на RPC |
| `--allow-custom-coinbase` | Разрешить аутентифицированному внешнему worker запросить свою выплату |
| `--purge-state` | Очистить изменяемое состояние и заново синхронизировать его с пиров |
| `--check-hardware` | Показать поддержку рабочего CPU и выйти, не затрагивая данные узла |

Параметры конкретного режима отклоняются там, где неприменимы.
`--cpu-threads` относится ко встроенному майнеру. Внешний режим требует
`--mining-key`, а `--allow-custom-coinbase` — одновременно внешний режим и
этот ключ.

`--purge-state` — инструмент ремонта и обновления, а не обычный параметр
запуска. Он сохраняет кошелёк, постоянные заголовки и идентичность пира, но
заставляет заново получить и аутентифицировать живое состояние.

Примеры:

```sh
# Ordinary node
parano1d --data-dir ~/.parano1d/data

# Internal miner using 12 logical CPUs
parano1d --mode miner --cpu-threads 12

# Node with a local external nonce worker
parano1d --mode extminer --mining-key 'LONG-RANDOM-TOKEN'
```

Оставляйте RPC на loopback, если он не защищён приватным или
аутентифицированным транспортом. Bearer-key аутентифицирует запросы, но не
шифрует их.

## Внешний майнер

`parano1d-miner` запрашивает уже доказанный неизменяемый шаблон и ищет только
его 128-битный nonce.

| Параметр | По умолчанию | Значение |
|---|---|---|
| `--rpc URL` | `http://127.0.0.1:9401` | JSON-RPC endpoint узла |
| `--key TOKEN` | — | Bearer-токен, совпадающий с `--mining-key` узла |
| `--threads N` | `0` | Потоки PoW; ноль использует все видимые логические CPU |
| `--coinbase ADDRESS` | — | Пользовательская выплата `o1…`, если узел явно разрешил |
| `--poll-ms MS` | `500` | Задержка перед запросом следующего шаблона |
| `--log LEVEL` | `info` | Фильтр журнала worker |
| `--check-hardware` | — | Показать поддержку рабочего CPU и выйти |

Обычный локальный запуск:

```sh
parano1d-miner \
  --rpc http://127.0.0.1:9401 \
  --key 'LONG-RANDOM-TOKEN' \
  --threads 12
```

Границы удалённого транспорта и пользовательской выплаты описаны в разделе
[Внешний майнер](../operate/external-miner.md).

## Клиент узла

`parano1d-cli` — тонкий клиент работающего Core. У него нет отдельного ключа;
операции кошелька выполняются через локальный JSON-RPC.

### Общие параметры

```text
-r, --rpc URL   RPC endpoint
-j, --json      raw JSON output
```

Стандартный endpoint — `http://127.0.0.1:9401`. Его можно изменить переменной
окружения `NOID_RPC`; параметр `--rpc` имеет приоритет.

Суммы в командах кошелька указываются в NOID, не более шести десятичных
знаков:

```text
1 NOID = 1,000,000 μNOID
```

### Узел и цепь

| Команда | Аргументы | Результат |
|---|---|---|
| `status` | — | Вершина, хеш, сложность и сводка активного состояния |
| `block-hash` | `HEIGHT` | Постоянный ID блока с nonce |
| `block-header` | `HEIGHT` | Структурированный постоянный заголовок |
| `header` | `HEIGHT` | Необработанный канонический 212-байтный заголовок в hex |
| `block` | `HEIGHT` | Необработанный полный блок в hex, пока сохранён |
| `history-step-terminal` | — | Текущий локальный terminal в hex |
| `tx` | `TXID` | Постоянное место подтверждения |
| `slot` | `INDEX` | Текущее содержимое слота |
| `utxos-of` | `o1…` | Текущие UTXO указанного адреса |
| `state` | — | Вместимость, заполнение и размер кодированного состояния |
| `epoch` | — | Текущий anchor пользовательской эпохи в 144 блока |

Примеры:

```sh
parano1d-cli status
parano1d-cli block-header 420
parano1d-cli block 420
parano1d-cli slot 9700063
parano1d-cli utxos-of o1...
```

`block` возвращает данные только внутри 18-блочного окна хранения тел.
`header` и `block-header` доступны для каждой канонической высоты постоянно.

### Сеть и майнинг

| Команда | Параметры | Результат |
|---|---|---|
| `peers` | — | Число подключённых пиров |
| `mining` | — | Сложность, следующая награда и состояние майнинга |
| `block-template` | `--miner-addr o1…` | Внешний шаблон майнинга, принадлежащий узлу |
| `submit-block` | `TEMPLATE_ID NONCE_HEX` | Отправить один 16-байтный nonce little-endian |

Команды внешнего майнинга низкоуровневые. `parano1d-miner` автоматически
обновляет шаблоны и кодирует nonce.

### Комиссии и mempool

```sh
parano1d-cli estimate-fee 2 --inputs 1
parano1d-cli mempool
parano1d-cli mempool-tx TXID
```

`estimate-fee` сообщает текущий минимум, принимаемый узлом для заявленного
числа живых входов и выходов. Строки mempool — логические intent
`PagedSpend`, а не отдельные физические страницы.

### Проверка адреса

```sh
parano1d-cli validate o1...
```

Команда сообщает корректность, каноническую форму bech32m и необработанный
32-байтный payload.

### Адреса кошелька

```sh
parano1d-cli address
parano1d-cli address --list
parano1d-cli address --new
parano1d-cli address --index 3
parano1d-cli address --use 3
```

`--new`, `--index` и `--use` — взаимоисключающие действия. Созданный адрес
остаётся неактивным до явного выбора. Отправка использует только UTXO
активного владельца и возвращает сдачу ему же.

### Баланс и UTXO

```sh
parano1d-cli balance
parano1d-cli utxos
parano1d-cli scan
```

`balance` отдельно показывает подтверждённые, зарезервированные исходящие,
ожидающие входящие и расходуемые суммы. `scan` заново загружает активного
владельца из проверенного постоянного индекса.

### Отправка

Предпросмотр:

```sh
parano1d-cli send o1... 10.5 --dry-run
```

Отправка с автоматической комиссией:

```sh
parano1d-cli send o1... 10.5
```

Точную комиссию в NOID задавайте только при необходимости:

```sh
parano1d-cli send o1... 10.5 --fee 0.012
```

Возвращаемый ID относится ко всей логической транзакции. Рекомендуется
автоматическая комиссия, поскольку заполнение состояния и relay-floor могут
измениться.

### История и чеки

```sh
parano1d-cli history
parano1d-cli history --last 20
parano1d-cli history --address o1...
```

Экспорт подтверждённого исходящего чека:

```sh
parano1d-cli receipt TXID > receipt.hex
```

Проверка:

```sh
parano1d-cli verify "$(tr -d '\n' < receipt.hex)"
```

Экспорт возможен только для локально сохранённого платежа другому владельцу.

### Остановка

```sh
parano1d-cli stop
```

Команда запрашивает корректное завершение демона. Она эквивалентна обычному
выходу из GUI, а не уничтожению процесса.

### Скрипты

Используйте `--json` и проверяйте код завершения:

```sh
height="$(
  parano1d-cli --json status |
    jq -er '.height'
)"
```

Человекочитаемый вывод и цвета относятся к представлению. Скрипты должны
обрабатывать JSON.
